# Hooks

Custom actions and filters fired by Extend WP. Each entry lists the name, type, parameters and where it is fired; the docblock above the `apply_filters` / `do_action` call is the full reference. Started 2026-10-12 — older hooks are documented in `docs/` and are added here as their files are touched.

| Name | Type | Parameters | Fired in | Since |
|---|---|---|---|---|
| `ewp_admin_ui_fields_enabled` | filter | `bool $enabled` — true on post, term and user edit screens (screen base `post`, `term`, `edit-tags`, `profile`, `user-edit`); `WP_Screen $screen` — current screen | `EWP_Admin_UI::is_fields_enabled()` (`includes/classes/ewp-admin-ui/class-ewp-admin-ui.php`), on `admin_body_class` and `admin_enqueue_scripts`. Turns the compact field look (`body.ewp-admin-ui-fields`: controls and repeaters inside Extend WP's own fields) on or off for a screen | 1.5.4 |
| `ewp_admin_ui_enabled` | filter | `bool $enabled` — true on options pages rendered by `templates/settings.php` (registered without `ext_callback`); `WP_Screen $screen` — current screen | `EWP_Admin_UI::is_enabled()` (`includes/classes/ewp-admin-ui/class-ewp-admin-ui.php`), on `admin_body_class` and `admin_enqueue_scripts`. Turns the options-page look (`body.ewp-admin-ui` + `assets/css/admin/ewp-admin-ui.min.css`) on or off for a screen | 1.5.4 |
| `ewp_column_` (`ewp_column_{$page_id}_column_content_filter`) | filter | `string $content` — cell HTML (default `''`); `array $item` — row; `string $column_name` — column key | `AWM_List_Table::column_default()` (`includes/classes/awm-list-tables/class-list-table.php`), for every list cell without its own renderer. Filox fills booking columns here (`ewp_column_flx_booking_column_content_filter`). To be mapped onto the DataViews list (phase 5) | 1.0.0 |
| `ewp_row_actions_` (`ewp_row_actions_{$page_id}_filter`) | filter | `array $actions` — action key => link HTML (Edit, Duplicate, Delete); `array $item` — row | `AWM_List_Table::column_*` title column (same file). Filox adds booking actions (`ewp_row_actions_flx_booking_filter`). To be mapped onto DataViews actions (phase 5) | 1.0.0 |
| `awm_custom_content_save_filter` | filter | `array $data` — posted data; `string $id` — content type id | `awm_custom_content_save()` (`includes/classes/awm-content-db-api/custom-content/content-functions.php`), before a content item is split into `_main` columns and `_data` meta | 1.0.0 |
| `awm_main_table_data_filter` | filter | `array $main` — `{ table_data: column => value, exclude: posted keys stored as columns }`; `string $id` — content type id; `array $data` — posted data | `awm_main_table_data()` (same file), on every content save (filox `client` sets the client name here) | 1.0.0 |
| `awm_meta_table_data_filter` | filter | `array $metas` — meta key => value; `string $id`; `array $data`; `string[] $exclude` | `awm_meta_table_data()` (same file), on every content save | 1.0.0 |
| `ewp_custom_content_save_action` | action | `string $id` — content type id; `int $object_id` — saved id; `array $data` — posted data | `awm_custom_content_save()` (same file), after `{type}_save_action` | 1.0.0 |
| `ewp_custom_content_delete_action` | action | `string $field` — content type id; `array $ids` — deleted ids (integers for `content_id`) | `awm_custom_content_delete()` (same file), after `{type}_after_delete_action`. The per-type `{type}_pre_delete_action` / `{type}_after_delete_action` receive `($ids, $where_clause)`; since 1.6.0 the WHERE's IN value is an array, not a `(1,2)` string | 1.0.0 |
| `ewp_db_shadow_enabled` | filter | `bool $enabled` — true when the `EWP_DB_SHADOW` constant is set and true | `EWP\Db\Shadow::enabled()` (`includes/classes/ewp-db/class-shadow.php`), on every `get_db_data()` / `update_db_data()` / `delete_db_data()`. Turns the old-vs-new WHERE comparison on or off per request; it never runs on production whatever this returns | 1.6.1 |
| `ewp_db_cache_table` | filter | `bool $enabled` — true for the `{type}_main` / `{type}_data` tables of registered content types; `string $table` — table name without the WordPress prefix | `EWP\Db\Read_Cache::enabled_for()` (`includes/classes/ewp-db/class-read-cache.php`), on every `AWM_DB_Creator::get_db_data()`. Return true only for tables written exclusively through `AWM_DB_Creator` (or whose raw `$wpdb` writers call `EWP\Db\Read_Cache::invalidate($table)`): with a persistent object cache, results survive between requests | 1.6.2 |
| `ewp_database_columns_dropped` | action | `string $tableName` — table name without the WordPress prefix; `string[] $removable` — columns removed | `AWM_DB_Creator::drop_columns()` (`includes/classes/awm-db/class-db-creator.php`), after the ALTER TABLE succeeded; reached directly or from a schema's `dropColumns` list on a version bump (`dbUpdate()`) | 1.5.9 |
| `ewp_database_truncated` | action | `string $tableName` — table name without the WordPress prefix | `AWM_DB_Creator::truncate_table()` (`includes/classes/awm-db/class-db-creator.php`), after every row was removed (TRUNCATE, or DELETE + AUTO_INCREMENT reset for tables referenced by a foreign key). Flush caches built from the table here | 1.5.9 |
| `ewp_database_dropped` | action | `string $tableName` — table name without the WordPress prefix | `AWM_DB_Creator::drop_table()` (`includes/classes/awm-db/class-db-creator.php`), after the table was dropped and its `ewp_version_{$table}` option deleted | 1.5.9 |
| `ewp_database_updated` | action | `string $table` — table name without the WordPress prefix; `array $tableData` — table definition (`data`, `primaryKey`, `index`, `foreignKey`, `version`); `string\|int $currentVersion` — schema version now stored in `ewp_version_{$table}` (autoloaded since 1.5.9) | `AWM_DB_Creator::dbUpdate()` (`includes/classes/awm-db/class-db-creator.php`), after a custom table was created or upgraded on a version change (`new AWM_DB_Creator($schema)`, content types via `awm_register_content_db`) | 1.0.0 |
| `ewp_request_is_front_end` | filter | `bool $front_end` — detected value | `EWP\Request_Context::is_front_end()` (`includes/classes/class-request-context.php`), at plugin load | 1.5.1 |
| `awm_case_fields_choices_filter` | filter | `array $fields` — `awmInputFields()` (case => label + `field-choices`); `string $meta` — meta key of the rows (`awm_fields` / `query_fields`); `string $db` — content type of the rows (`ewp_fields` / `ewp_search`) | `AWM_API::case_fields()` (`includes/classes/awm-api/class-awm-api.php`), behind `GET extend-wp/v1/get-case-fields` (the "Field type configuration" box) | 1.5.1 |
| `ewp_allowed_meta_keys` | filter | `string[] $keys` — meta keys the save may write; `string $view` — `post`, `term` or `user`; `int $object_id` — object being saved; `string $subtype` — post type, taxonomy or `''` | `EWP_Meta_Save_Guard::allowed_keys()` (`includes/classes/class-meta-save-guard.php`), on `save_post`, `edit_term`, `create_term`, `profile_update` and `user_register` saves. Capability and role keys are removed after it | 1.5.5 |
| `ewp_gutenburg_blocks_filter` | filter | `array $blocks` — block id => definition (`namespace`, `name`, `title`, `render_callback`, `attributes`, `priority`, …) | `EWP_Dynamic_Blocks::definitions()` (`includes/classes/ewp-gutenburg/class-register.php`), once per request on `init` (and on `rest_api_init` for the preview routes). **Runs on every request, front end included**: keep definitions cheap. A select's `callback` runs only for the block editor payload (`enqueue_block_editor_assets`); a select with `object_search` never lists options. See `docs/gutenberg-blocks.md` | 1.0.0 (lazy options 1.5.8) |
| `awm_object_search_capability` | filter | `string $capability` — post type `edit_posts`, taxonomy `assign_terms`, else `manage_options` (1.5.8; before: always `manage_options`); `string $object_type` — `{group}:{slug}` searched, `''` when unknown (1.5.8) | `EWP\Search\Object_Search::capability()` (`includes/classes/ewp-search/class-object-search.php`), on every `extend-wp/v1/objects/search`, `wp ewp objects search` and `ewp-system/search-objects` call | 1.5.0 |
| `awm_add_meta_boxes_filter` | filter | `array $boxes` — box ID => box (`title`, `postTypes`, `library` or `callback`, …); `int $flag` — always 1 | `AWM_Meta::meta_boxes()` (`includes/classes/class-extend-wp.php`) when rendering; `EWP_Meta_Save_Guard::boxes()` on save | 1.0.0 |
| `awm_add_term_meta_boxes_filter` | filter | `array $boxes` — box ID => box (`title`, `taxonomies`, `library` or `callback`, …) | `AWM_Meta::term_meta_boxes()` when rendering; `EWP_Meta_Save_Guard::boxes()` on save | 1.0.0 |
| `awm_add_user_boxes_filter` | filter | `array $boxes` — box ID => box (`title`, `library` or `callback`, …); `int $flag` — always 1 | `AWM_Meta::user_boxes()` when rendering; `EWP_Meta_Save_Guard::boxes()` on save | 1.0.0 |
